# Making levels

flezzle-rs plays levels authored in [LDtk](https://ldtk.io/), the free,
open-source 2D level editor. This page is the contract between the editor
and the runner, and the shortest path to a level of your own.

## Install LDtk 1.5.3

The runner tracks LDtk's JSON schema through `bevy_ecs_ldtk` 0.15, which
supports **LDtk 1.5.3**. Newer LDtk versions may write fields the runner
doesn't understand yet; older ones lack fields it expects. Download the exact
version from the [LDtk releases](https://github.com/deepnight/ldtk/releases)
page rather than the front-page "latest".

## Start from the template

1. Copy `assets/levels/template.ldtk` next to itself under a new name (the
   file must stay in `assets/levels/` — tileset paths inside it are relative:
   `../atlas/…`).
2. Open the copy in LDtk. You'll see one small level with flat ground, a
   player, and a chest.
3. Draw and save. Saving is what bakes the pretty auto-tiles; levels
   generated by `tools/ldtk_gen.py` look plain until you do this once.
4. Play it: `cargo run -- levels/your-level.ldtk`, or add it to
   `assets/levels/index.json` to get it in the web page's level list, or use
   the web page's **open your own** file picker without adding anything.

Don't rename or delete layers, entity definitions, or IntGrid values — the
runner keys on them (below). Adding new ones is harmless until the runner
learns about them.

## What the runner understands

**Layers** (top to bottom in the editor):

| Layer | Type | Runner behaviour |
|---|---|---|
| `Entities` | Entities | Spawns the entities below |
| `Wall_shadows` | AutoLayer | Drawn only |
| `Collisions` | IntGrid | **1 dirt** and **3 stone** become solid walls (merged into rectangles); **2 ladder** cells are climbable |
| `Bg_textures` | AutoLayer | Drawn only |

**Entities:**

| Entity | Behaviour | Fields the runner reads |
|---|---|---|
| `Player` | You. Exactly one per level. Bottom-centre pivot. | `items` — printed with **P** (debug) |
| `Mob` | Patrols between its position and its `patrol` points; kinematic (pushes, isn't pushed) | `patrol` (array of points) |
| `Chest` | Heavy dynamic box you can shove | — (`content` is ignored for now) |
| `Pumpkins` | Decoration | — |
| `Door` | Ignored for now | — |

**Level:** the runner spawns the first level in the file (`LevelSelection::index(0)`)
and, if it has neighbours in the world, loads those too and follows the
player across level boundaries (see `example_world.ldtk`). The level's
background colour becomes the clear colour. Keep the player *inside* solid
ground boundaries; there is no kill plane yet.

**Tilesets:** use the two bundled ones (`SunnyLand_by_Ansimuz-extended.png`,
`MV Icons Complete Sheet Free - ALL.png`). A level that references any other
image will render those tiles blank in the browser, because uploaded levels
only see the bundled atlas. Custom tilesets are on the roadmap (F9).

## Authoring in ASCII instead

`tools/ldtk_gen.py gen levels-src/NAME.txt assets/levels/NAME.ldtk` turns a
text map into a level using the template's definitions:

```
.  empty     #  dirt     =  stone     H  ladder
P  player    C  chest    M  mob       m  mob patrol target (same row)
p  pumpkins  ;  comment line
```

The three bundled starter levels are made this way (`levels-src/`). The
generator paints the Collisions layer from a tile table learned from the
sample level's baked auto-tiles, so results are recognisable but not what
LDtk's real rules produce — open the file in LDtk and save to upgrade it.

## Sharing a level

A level is one `.ldtk` file. Anyone with the web build can open it with the
file picker; no server round-trip, nothing uploaded anywhere. (Bundling
levels into the web page for a shared collection is later roadmap work.)
